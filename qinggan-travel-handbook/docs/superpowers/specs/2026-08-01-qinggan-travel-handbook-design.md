# 《向西而行｜2026青甘大环线自由探索手册》产品与技术设计

日期：2026-08-01
状态：已批准，待实施计划

## 1. 产品定位

这是一份送给固定六人旅行团队的私人数字旅行手册。它不是旅行社行程表，也不是导航、预订或社交产品。产品负责提供可信、清楚、有故事感的地点信息和自由探索建议，不替用户决定哪一天去哪里，也不规定几点出发。

核心体验原则：

- 自由探索：所有地点随时可看，不绑定 Day 1 至 Day 8。
- 信息可靠：建议尽量具体，危险和不确定内容明确说明。
- 照顾隐于设计：使用清楚的大字、宽触控区、充分留白和客观体力提示，同时隐藏内部用户画像与身份标签。
- 地图是入口，不是单点故障：高德地图失败时，核心内容仍可访问。
- 记录极简：只保存“已去过 / 未去”，不衍生笔记、照片或日期。

## 2. 用户可见范围

### 2.1 查看

- 真实地图与建议探索顺序
- 地点攻略、常规玩法和合法安全的非常规玩法
- 拍照指南、动作和穿搭建议
- 预约信息、避坑提示、宗教、生态与安全提醒
- 可顺路组合地点
- 本地整理的沿途热点和彩蛋
- 地点详情页的当地天气
- 出发前复核清单

### 2.2 简单记录

- 每个地点只有“已去过 / 未去”两种状态。
- 状态由用户手动切换。
- 状态保存在浏览器 localStorage。
- 足迹页只汇总已去地点和数量。

### 2.3 明确不做

- 登录、注册、后台、权限
- 文字笔记、心情、评分、日期和时间记录
- 照片上传、同步或分享
- 实时定位、导航、出发提醒或固定日程
- 酒店、门票或其他支付
- 自动抓取新闻、社交内容或热点
- 自动截图、缓存或再分发高德地图瓦片
- 完整离线应用承诺；降级能力以网页主体已加载为前提

## 3. 信息架构

移动端底部导航保留五个高频入口：

1. 首页
2. 探索地图
3. 地点指南
4. 拍照宝典
5. 我的足迹

沿途彩蛋与出发准备在首页提供醒目入口，不挤占底部导航。桌面端使用顶部导航和杂志式内容版面，但保持相同页面结构。

### 3.1 Intro 旅行序章

首次访问播放 10 至 15 秒的开场：

1. 浅色纸张展开。
2. 本地真实中国轮廓出现。
3. 杭州盖下“出发”印章。
4. 飞机沿弧线飞抵西宁。
5. 六位旅行人物出现。
6. 人物进入商务车。
7. 青甘路线依次点亮。
8. 标题“向西而行”出现。
9. 用户点击“开始探索”进入首页。

动画使用 GSAP 时间线，提供始终可见的跳过按钮。首次完整播放或跳过后，在 localStorage 写入已观看状态；后续默认进入首页。首页提供“重播序章”。系统启用减少动态效果时，使用缩短的淡入版本。

### 3.2 Home 首页

首页以“山河档案”杂志封面为核心，不展示天气列表或固定日程。主要内容：

- 项目标题与一句自由探索引导语
- 探索地图主入口
- 地点指南、拍照宝典、沿途彩蛋、我的足迹入口
- 出发准备入口
- 已探索地点数量
- 一处可更换的精选地点内容

首页不根据日期推断用户应该前往的地点，也不催促用户赶路。

### 3.3 Map 探索地图

正常状态使用高德地图 JS API：

- 显示杭州至西宁的飞行关系。
- 绘制西宁出发并回到西宁的青甘环线。
- 未去地点、已去地点和沿途彩蛋使用不同标记。
- 点击标记打开移动端底部景点卡片；桌面端打开侧边详情卡片。
- 地图卡片可进入地点详情或切换已去状态。

建议探索顺序：

西宁 → 门源 → 张掖 → 嘉峪关 → 瓜州 → 敦煌 → 阿克塞 → G315 → 乌素特水上雅丹 → 大柴旦 → 茶卡 → 青海湖 → 西宁。

地图加载失败时，立即显示本地“青甘环线地理示意底图”：

- 参考用户提供的路线闭环图，但不直接复制社交平台截图、文字、水印或地图瓦片。
- 依据真实经纬度排布路线节点，使用选定的“山河档案”视觉重新绘制。
- 显示清晰的大号地名、橙色路线和可点击节点。
- 标注“路线示意，非导航地图”。
- 保留地点详情入口、顺路组合和已去状态切换。
- 提供“重新加载真实地图”按钮。

### 3.4 Places 地点指南

以大图列表与紧凑列表两种密度适配屏幕，默认使用易浏览的大图列表。分类筛选：

- 文化遗址
- 湖泊盐湖
- 草原雪山
- 沙漠雅丹
- 公路风景
- 沿途彩蛋

筛选状态写入 URL 查询参数，便于刷新后保持当前浏览位置，但不构成社交分享系统。

### 3.5 PlaceDetail 地点详情

统一显示以下内容：

- 一句话判断
- 推荐指数与是否值得专程
- 建议停留时间、最佳观赏时间、适合天气
- 步行强度，以及海拔、台阶、路面和休息条件等客观提示
- 常规玩法和合法安全的非常规玩法
- 拍照机位、镜头倍率、单人姿势和六人合影方法
- 穿搭建议
- 预约渠道和建议提前时间
- 避坑提示
- 宗教、生态或安全提醒
- 可顺路组合地点
- 已去过切换按钮
- 该地点最新天气、数据更新时间和失败状态

页面和数据不呈现内部用户画像或身份标签。视觉上的照顾通过版式实现，不用文案解释。

地点天气由浏览器直接请求天气接口，不经过自建后台。仅在地点详情页请求对应坐标天气。请求失败时显示上次成功缓存及更新时间；没有缓存时显示克制的不可用提示，不影响攻略阅读。

### 3.6 PhotoGuide 拍照宝典

覆盖八类场景：

- 湖泊和盐湖
- 沙漠
- 草原和雪山
- 丹霞地貌
- 古建筑和寺院
- 公路和车辆
- 城墙和遗址
- 日落和剪影

每类包含推荐机位、镜头倍率、三个单人动作、六人构图、常见错误和穿搭色系。固定增加“六人素材最小公式”：

- 10 秒稳定全景
- 10 秒人物行走
- 一张六人完整合影

公路拍摄优先推荐安全停车区、观景台或远离车流的位置，让取景和通行都更从容。

### 3.7 Highlights 沿途彩蛋

仅使用用户在 2026-08-01 提供的七项内容：

- 张掖热气球
- 鸣沙山星空演唱
- 鸣沙山骆驼红绿灯
- 茶卡夜游
- 湟鱼洄游
- 可可西里网红狼
- 黑独山禁游区域争议

每项显示地点、为什么出圈、是否顺路、是否值得专程、安全提示和 A/B/C 可信度标签。内容为本地结构化数据，不在页面打开时抓取新闻。黑独山和可可西里相关内容以风险辨识与克制提醒为核心，不提供进入禁区、接近或投喂野生动物的方法。

### 3.8 Footprints 我的足迹

- 只显示已勾选地点。
- 显示已探索数量、进度和地图印章。
- 不显示日期、文字、照片、评分或时间线。
- 空状态引导用户返回地图或地点指南，不制造完成任务的压力。

### 3.9 Preparation 出发准备

以“出发前建议复核”呈现，不提供提醒通知。内容：

- 莫高窟票务
- 张掖活动时间
- 鸣沙山活动安排
- 水上雅丹开放情况
- 茶卡和青海湖天气
- 主要道路临时管控
- 无人机规定
- 景区开放时间

准备内容不照搬用户参考截图中的药品、无人机或活动建议；涉及健康、药物、飞行和临时管控时，只使用克制、可核验且不替代专业判断的表述。

## 5. 安全与内容红线

系统从内容源头排除以下风险行为；用户页面只呈现客观事实、现场规定与温和建议，不使用命令式或管教式口吻：

- 进入禁区或无人区
- 翻越围栏
- 站在公路中央拍照
- 踩踏花田或脆弱盐壳
- 攀爬雕塑、遗址或受保护设施
- 追逐、接近或投喂野生动物
- 在未确认规定时飞行无人机
- 为打卡强行赶路或在疲劳状态继续驾驶

用户可见的安全表达示例：

- “该区域开放情况以现场告示为准，留在开放范围内观赏更安心。”
- “公路取景更适合在观景台或安全停车区完成。”
- “花田沿步道观赏，画面更完整，也能把花期留给后来的人。”
- “遇见野生动物，保持自然距离更容易看到它原本的状态。”
- “无人机规定可能临时调整，起飞前可先看景区当日公示。”

宗教场所使用尊重、事实化的说明，不猎奇、不替用户作价值判断。高原和体力相关内容只呈现客观环境与节奏建议，不贴身份或身体标签。

## 6. 视觉设计

选定方向：“山河档案”。视觉参考文件为 `design/visual-direction-selected.png`；用户提供的五张截图只用于路线表达、活动组织和准备清单的灵感，不作为可直接发布的内容或底图。

视觉比例：

- 60% 高级旅行杂志
- 25% 克制的旅行手账
- 15% 轻童趣动画

色彩令牌：

- 沙漠米：页面主背景
- 天空蓝：空气感和地图水域
- 湖水青：信息强调与摄影章节
- 日落橙：主按钮、路线和印章
- 深棕：标题与正文

设计语言：

- 大幅真实风景负责情绪，正文区保持安静。
- 使用细等高线、山形、邮戳和路线批注作为轻装饰。
- 纸张纹理非常浅，不做厚重、泛黄或破损的羊皮纸。
- 主要按钮高度不低于 48px，触控区域不低于 44×44px。
- 移动端正文基准约 17–18px，行高充足；桌面端控制长文本行宽。
- 标题使用现代宋体风格，正文使用清晰黑体风格，并设置系统字体回退。
- 桌面端使用杂志跨页感和更宽的地图，不简单等比放大手机布局。
- 不使用旅行社蓝橙模板、电商促销组件、后台仪表盘或卡片套卡片。

## 7. 技术架构

### 7.1 技术栈

- Vue 3
- Vite
- TypeScript
- Vue Router
- Pinia
- GSAP
- 高德地图 JS API
- Lucide Vue
- CSS Variables、全局版式样式与组件级样式
- Vitest

不引入后台服务。应用构建为静态单页应用，可部署到支持 SPA 回退的静态托管平台。

│  ├─ components/
│  │  ├─ common/

### 7.3 内容模型

地点内容由 TypeScript 数据文件导出，页面组件只消费统一类型。核心字段：

```text
Place
├─ id / slug / name / region
├─ category / routeOrder / coordinates
├─ summary / recommendation / worthDetour
├─ suggestedDuration / bestViewingTime / suitableWeather
├─ walkingIntensity / physicalNotes
├─ conventionalPlay / unconventionalPlay
├─ photoGuide / soloPoses / groupComposition
├─ outfitAdvice
├─ reservation
├─ pitfalls / safety / etiquette / ecology
├─ nearbyCombinationIds
└─ weatherCoordinates
```

`physicalNotes` 只存海拔、路面、台阶、距离和休息条件等事实，不存用户画像评价。

已去状态不写回地点内容，而是独立保存为 `{ [placeId]: boolean }`，便于内容与个人状态解耦。

### 7.4 本地状态

localStorage 键使用带版本前缀的命名：

- `westward:v1:visited`
- `westward:v1:intro-seen`
- `westward:v1:weather-cache`

读取时进行容错解析。损坏或旧格式数据回退为空状态，不阻止页面启动。

### 7.5 外部服务

高德地图：

- 通过环境变量读取 JS API Key 和安全配置。
- Key 缺失或脚本失败时进入本地路线底图。
- 核心内容与地图实例解耦。

天气：

- 首选 Open-Meteo Forecast API，不需要自建后台或在前端保存私密令牌。
- 浏览器按地点坐标直接请求天气服务。
- 仅请求地点详情需要的当前和短期数据。
- 设置请求超时和本地缓存，显示更新时间。
- 天气失败不影响地点内容和已去状态。

## 8. 组件边界与数据流

- `MapProvider`：只负责加载和销毁高德实例，向上报告成功或失败。
- `RouteMap`：消费路线坐标和地点状态，绘制折线和标记。
- `FallbackRouteAtlas`：使用同一份路线数据绘制本地底图与可点击节点。
- `PlaceCard`：展示地点摘要，不直接读取 localStorage。
- `VisitedToggle`：调用 Pinia store 切换状态。
- `WeatherPanel`：调用天气服务，处理加载、缓存、失败和更新时间。
- `PlaceDetailView`：按 slug 查找地点并组合各内容组件。

数据流：本地内容数据进入页面与地图；Pinia 管理访问状态并持久化；天气服务只向 `WeatherPanel` 返回展示模型。任一外部服务失败都不会污染本地内容状态。

## 9. 异常与降级

- 高德 Key 缺失、脚本失败或超时：显示本地路线底图。
- 天气请求失败：优先显示带时间戳的缓存；没有缓存时显示不可用提示。
- 地点 slug 不存在：显示友好的未找到页面和返回地点列表入口。
- 图片失败：保留文字内容，使用统一的低干扰背景色，不造成布局跳动。
- localStorage 不可用：状态保留在当前会话内，并提示本次无法持久保存。
- 动画资源失败：直接显示标题和“开始探索”。

## 10. 验证与验收

自动检查：

- TypeScript 类型检查
- 数据完整性：16 个地点必填字段、唯一 id/slug、合法坐标和组合引用
- 地点分类筛选
- 已去状态切换、刷新恢复和损坏数据容错
- Intro 首次播放、跳过、后续直达和重播
- 天气缓存与失败降级
- 生产构建

人工检查：

- 手机端滚动、触控与底部导航
- 桌面端杂志版式和地图空间
- 地图成功与失败两种状态
- 地图标记与底部卡片
- 全站自由浏览，不出现固定日期或强制日程
- 全站内部画像与身份敏感词扫描
- 危险地点与热点的安全提示
- 减少动态效果模式
- 图片慢加载与外部服务失败场景

完成标准：

- `npm install` 成功。
- 类型检查和测试通过。
- `npm run build` 成功。
- README 说明启动、高德 Key、地点内容修改、部署和 localStorage 保存机制。
- 不存在登录、后台、笔记、照片上传、实时定位、导航、支付或社交分享功能。
